# 顺心控车 iOS 版（1.12）

> 与 Android 1.12 同一套协议、同一套决策逻辑。**差别只在系统能力**：iOS 拿不到 MAC 地址、没有前台服务，省电模型因此完全不同（见第 4 节）。
> 本目录是可以直接编译出**未签名 .ipa** 的完整 Swift 工程，配合巨魔（TrollStore）安装，永久不掉签。

---

## 0. 一句话回答「怎么编译」

**Windows 上编不了 iOS**，这不是配置问题：iOS 应用必须用 Apple 的 Xcode 编译，Xcode 只跑在 macOS 上。Swift 官方虽然出了 Windows 版，但它**没有 iOS SDK**，编出来的是 Windows 程序。

所以本工程自带一条**免费云编译流水线**：把代码推到 GitHub，GitHub 用免费的 macOS 机器替你编译，产出未签名 ipa 给你下载。**你不需要 Mac，也不需要装 Xcode，更不需要 Apple 开发者账号。**

整个流程只有三步：

```
① 代码推到 GitHub  →  ② 等 3~5 分钟自动编译  →  ③ 下载 ipa 用巨魔安装
```

## 1. 保姆级：从零到装进手机

### 1.1 建一个空仓库

1. 打开 https://github.com/new
2. **Repository name** 填 `sxkc-ios`（随便起）
3. 选 **Private**（私有）。**别选 Public** —— 工程里有你的账号协议细节，而且私有仓库的免费额度对个人完全够用（每月 2000 分钟，一次编译约 4 分钟）。
4. 下面的 "Add a README file / .gitignore / license" **全部不要勾**，建一个纯空仓库。
5. 点 **Create repository**。

### 1.2 把代码推上去

**先把本目录的压缩包解压到一个不含中文和空格的路径**，例如 `D:\sxkc-ios`。
然后在那个目录里打开命令行（资源管理器地址栏输入 `cmd` 回车），执行：

```bash
git init
git add -A
git commit -m "SXKC iOS 1.12"
git branch -M main
git remote add origin https://github.com/你的GitHub用户名/sxkc-ios.git
git push -u origin main
```

`git push` 时会弹窗让你登录 GitHub：

- 如果弹出浏览器 → 点授权即可（Git for Windows 自带的凭据管理器）；
- 如果要你输入密码 → **不能填账号密码**，要填 **Personal Access Token**：
  GitHub → 右上角头像 → Settings → Developer settings → Personal access tokens →
  **Tokens (classic)** → Generate new token → 勾选 **`repo`** → 生成后复制那串 `ghp_...`，
  粘贴到密码位置（用户名填你的 GitHub 用户名）。

> 检查是否成功：刷新仓库页面，应该能看到 `SXKC/` 目录、`project.yml`、`.github/` 三项。

**如果你不想用命令行**，也可以网页上传：

1. 仓库页面点 **Add file → Upload files**
2. 把解压出来的**所有内容**（`SXKC` 文件夹、`project.yml`、`README.md`、`build-local.sh`、`.gitignore`、`.github`）一起拖进去
3. 点 **Commit changes**

⚠️ 网页上传最容易踩的坑：**`.github` 是隐藏文件夹**，Windows 资源管理器默认不显示，很容易漏掉。漏了它 GitHub 就不会自动编译。
先在资源管理器「查看」里勾上「**隐藏的项目**」，确认 `.github\workflows\build-ipa.yml` 存在再拖。
如果实在传不上去，就用命令行（`git add -A` 会把隐藏文件一起加进去，不会漏）。

### 1.3 等它自动编译

1. 打开仓库页面的 **Actions** 标签
2. 左边会有一个叫 **build-ipa** 的流程正在跑（黄色小圆点转圈）
3. 点进去看实时日志，全程约 **3~5 分钟**（第一次要装 XcodeGen，稍慢）
4. 看到绿色 ✅ 就是成功了

日志里你会依次看到：`显示 Xcode 版本` → `安装 XcodeGen` → `生成 Xcode 工程` → `编译（不签名）` → `打包成 ipa` → `上传产物`。

### 1.4 下载 ipa

1. 在那次运行页面的**最下方**，找到 **Artifacts** 区域
2. 点 **SXKC-unsigned-ipa**，下载得到一个 zip
3. 解压，里面就是 `SXKC-unsigned.ipa`

> Artifacts 默认保留 30 天，过期了重新跑一次就行（Actions 页面 → 左侧 build-ipa → 右上 **Run workflow**）。

### 1.5 传到 iPhone

Windows 上没有 AirDrop，最省事的三条路：

- **微信**：发给「文件传输助手」→ 手机端打开 → 右上角 `···` → **用其他应用打开** → 存到「文件」
- **QQ**：发到「我的电脑」→ 手机端下载 → 存到「文件」
- **网盘**：阿里云盘 / 百度网盘，iPhone 里下载后同样「存到文件」

只要 ipa 出现在 iPhone 的「**文件**」App 里就行。

### 1.6 用巨魔安装

**方式一（最快）**：在「文件」App 里点一下 `SXKC-unsigned.ipa` → 弹出分享面板 → 选 **TrollStore** → **Install**。

**方式二**：打开 TrollStore → 右上角 **+** → **Install IPA File** → 在文件选择器里找到那个 ipa → 安装。

装完桌面会出现「**顺心控车**」图标（深蓝底、白色汽车 + 绿色锁）。

> TrollStore 装的应用是**永久签名**，不会 7 天掉签，也不用连电脑。
> Bundle ID 是 `cn.sxkc.lite`，和 Android 版完全不冲突，两台手机可以同时装。

## 2. 第一次打开要做的几件事

### 2.1 允许蓝牙

第一次启动会弹「App 想要使用蓝牙」→ **必须点允许**。拒绝了就要去
设置 → 顺心控车 → 蓝牙 里重新打开。

### 2.2 登录

用和 Android 版**完全一样的账号密码**（`distribute=sxkc`、密码 SHA-1 大写后上传）。
登录成功会拿到 `tid` 和 `btkey`，自动存本地，之后不用再登。

### 2.3 配对车机（只需一次，但必须做）

这是 iOS 和 Android 最大的操作差异：**iOS 拿不到车机 MAC 地址**，只能第一次手动连一次，让系统记住它。

1. 主界面右上角点 **诊断**
2. 点 **全量扫描**
3. 列表按信号强弱排序，找那个**连上后带绿色 `FFE0` 标记**的设备
   （车机排在哪个位置不确定，因为它广播里可能不带服务 UUID —— 那就挨个点，看日志里哪个出现 `GATT` 表包含 `FFE0`）
4. 连上后日志会打：`✓ 指纹命中 0xFFE0/0xFFE1，已记住这台车机`
5. 点 **开锁帧** 试一下 —— 车锁动了，说明整条链路通了

**这一步过了，后面所有功能才有意义。** 如果这一步不过，先别管自动模式。

### 2.4 想用自动模式，先标定距离

同一个诊断页里有 **距离标定**：

1. 站在车前 **1 米**，点「开始 30 秒标定」，人别动
2. 30 秒后看「平均 xxx dBm」
3. 回主界面，把「**开锁信号门限**」设成比这个平均值 **高 5~8 dBm**（比如标定 -63，门限就设 -58 ~ -55）

门限设太高（比如 -50）会导致走到车边也不解锁；太低（比如 -85）会导致在楼上就把车解开。

### 2.5 换账号（换手机号登录）

主界面滑到底，有一张「账号」卡片：

1. 点 **退出登录** → 弹出选项 → 再点 **退出登录** 确认；
2. App 回到登录页，**手机号会预填上次那个**，改成新号 + 输密码即可；
3. 已记住的车机**不会丢**，新账号进来直接就能连，不用重新扫。

> 别用「删除 App 再重装」来换账号。iOS 拿不到车机 MAC，重装后 identifier 变了，
> 而车机平时不广播 —— 很可能就再也扫不回来了（安卓还能按 MAC 重连，iOS 没这条路）。
> 这也是这一版把「同时忘记车机」这个勾选框**刻意去掉**的原因。

## 3. 常见问题

### 编译失败 / 红色 ❌

点进失败的那一步看日志最后 30 行，**把日志发我，我直接改**。本工程在 Windows 上无法本地编译验证，第一次跑有可能有几处报错，属于正常。

最常见的两类：

| 日志关键字 | 原因 | 处理 |
|---|---|---|
| `error: cannot find 'xxx' in scope` | 我漏了某个引用 | 发我，改一行就好 |
| `No signing certificate` | 签名没关干净 | 检查 workflow 里的 `CODE_SIGNING_ALLOWED=NO` 是否被改动过 |

### Actions 标签是空的 / 没有 build-ipa

说明 `.github/workflows/build-ipa.yml` 没传上去（隐藏文件夹被漏掉了）。
在那个路径手动新建文件也行：仓库 → **Add file → Create new file** → 文件名填
`.github/workflows/build-ipa.yml` → 把本目录同名文件的内容整段粘进去 → Commit。

### 巨魔装的时候提示 "This app cannot be installed"

- 确认装的是**未签名**的 `SXKC-unsigned.ipa`（如果你自己签过名反而会冲突）
- 确认 iOS 版本在 TrollStore 支持范围内（大致 iOS 14.0–16.6.1，部分 17.0）
- 在 TrollStore 里长按该 App → **Reinstall** / `ldid` 重签一次

### 打开就闪退

巨魔装的应用如果崩溃，多半是**签名 entitlements 不完整**。处理：
TrollStore → 该 App → **Advanced** → 开启 `Enable JIT` 或 `ldid` 重签。
仍不行就把崩溃日志（设置 → 隐私与安全性 → 分析与改进 → 分析数据，找 `SXKC` 开头的）发我。

### 自动模式在后台"不工作"

先分清是哪种情况：

| 现象 | 原因 | 能修吗 |
|---|---|---|
| 锁屏后走到车边没自动开 | App 被系统挂起，且断线后系统还没重连上 | 等 2~3 秒；或直接进 App 点开锁 |
| 关掉自动模式开关后还在连 | 关开关只停判定，不会主动断开（保持连接更省得重连） | 正常，不影响功耗 |
| 杀掉 App 后彻底没反应 | iOS 不允许后台自启 | ❌ 无解，手动打开一次 |
| 重启手机后没反应 | 同上，且没有开机广播可监听 | ❌ 无解，手动打开一次 |

只要 App 还活着（没上滑杀掉），`bluetooth-central` 后台模式会替你维持连接，
来一帧就醒一次，这是 iOS 能给到的最好状态。详见第 4 节。

## 4. iOS 与 Android 的真实差异（提前说清，别抱错期待）

| 能力 | Android 1.12 | iOS 1.12 |
|---|---|---|
| 手动开锁 / 锁车 | ✅ 蓝牙优先，失败转网络 | ✅ **一样，而且通常更快**（不用等重连） |
| 纯网络开锁 / 锁车按钮 | ✅ | ✅ |
| 蓝牙连不上自动转网络 | ✅ | ✅ |
| 回执后二次核实（防假成功） | ✅ | ✅ |
| 换账号 / 退出登录 | ✅ 底部账号卡片 | ✅ 底部账号卡片（iOS 用弹出选项） |
| 靠近自动解锁 | ✅ 前台服务，1.5 秒一拍 | ✅ **事件驱动，连上即判** |
| 离开自动落锁 | ✅ 走开 30 秒后 | ⚠️ **蓝牙一断开就锁**（后台没有可靠定时器） |
| 后台常驻 | 前台服务 + 通知栏 | 只有 `bluetooth-central` 后台模式 |
| 开机自启 | ✅ | ❌ 系统不允许 |
| 白名单引导 / 省电设置 | ✅ | ❌ 无对应概念 |
| 连接间隔省电档 | ✅ | ❌ 无此 API |
| 运行日志落盘 | ✅ | ✅（`文件` App 里可导出） |

**后台自动逻辑，1.12 是这样做的：一个定时器都没有。**

安卓 1.11 那套「休眠状态机 + 运动传感器 + 兜底闹钟」，在 iOS 上是**负优化**，一行都没搬。
原因很直接：安卓的后台会真的把 CPU 叫醒、真的一直耗电，所以必须自己管节拍；
而 iOS 的 `bluetooth-central` 后台模式下，BLE 连接由系统维持，App 进程被挂起时几乎不耗 CPU，
只有车机推来一帧才会把它唤醒几毫秒。

所以 iOS 版只认三个事件：

1. **连上**（含系统后台自动重连）→ 判「该不该开锁」；
2. **断开** → 判「该不该立刻锁车」；
3. **状态帧**（车机 3 秒一帧）→ 顺手再判一次。

人车分离时没有任何事件，引擎完全不跑。这就是 iOS 上的省电答案。

还有一个 Android 没有、iOS 独占的能力：**断线后系统会自动重连**。只要 App 没被杀，
你走远再回来，`didConnect` 自己会回来，不需要任何"重连定时器"。

**必须提前知道的三个限制（都是系统级的，改不了）：**

- 「离开后延时 N 秒再锁车」做不了：后台没有可靠的定时器。所以改成**断开即锁**，
  并且只在「本次到访确实开过锁」时才锁，避免路过连一下就锁别人的车。
- 后台读不到 RSSI（系统限流），所以「靠近」的判据是：**有新鲜信号就按你设的门限，
  没有信号就信「能连上了」**。门限在后台基本不起作用，这是取舍，不是 bug。
- 手动上滑杀掉 App、或手机重启后，iOS 不会自动拉起，需要你手动打开一次。

所以建议：**iOS 当"手动控车 + 事件驱动的自动模式"用，最稳的主力还是 Android 那台。**

## 5. 1.12 这一版做了什么

### 新增：账号卡片 + 退出登录

| 项 | 说明 |
|---|---|
| 主界面底部「账号」卡片 | 显示打码手机号 `138****8888`，右边一个「退出登录」 |
| 弹出选项确认 | iOS 的 Alert 放不了勾选框，改成先弹选项再执行，一步到位 |
| 退出时清内存会话 | 断蓝牙、清 btkey/tid/解密密钥、清车辆状态，防止换号后拿旧 tid 控车 |
| 登录回调作废 | 退出瞬间若有登录在飞，回来会按会话代号丢弃，不会把旧账号写回本地 |
| 车机记录保留 | 只清账号，`identifier` 一直留着（见 2.5 的说明） |

### 改：自动模式从「定时器链」改成「纯事件驱动」

| 改动 | 说明 |
|---|---|
| 删掉 Timer 循环 | iOS 后台 Timer 必被挂起，留着只是前台空转，后台误导 |
| 三个事件驱动决策 | 连上判开锁、断开判锁车、状态帧顺手判一次 |
| 断开即锁 | 替代安卓的「走开 30 秒后锁」，只用后台能保证的东西 |
| 后台 RSSI 抓不到时的口径 | 有新鲜信号按门限，没有就信「连上了」 |
| 网络轮询改触发式 | 原来靠定时器每分钟问一次，现在只在「回到前台」时补一次 |
| 界面去掉假的「延时落锁」滑条 | 后台做不了的事不该留在界面上骗人 |

### 保留自 1.10 的修复

| 改动 | 说明 |
|---|---|
| 修 P0：站车旁锁车后自己解锁 | `markDone` 锁车后标为「本次到访已处理」 |
| 修 P0：下车车辆自锁被立刻解开 | `Logic.suppressUnlockOnArmedFlip()` |
| 开锁也做回执核实 | `Logic.verify()` 三条件放弃（超 20 秒 / 意图已变 / 已补一次） |
| 核实加 6 秒静默期 | 否则每条指令都会发两遍 |
| 日志落盘 | `Documents/logs/run.log`，512KB 滚一代 |
| 最低版本 iOS 14.0 | 覆盖更多巨魔机型 |

## 6. 代码结构

```
SXKC/
├── SXKCApp.swift              # 入口
├── Core/
│   ├── Hex.swift              # 对应 Hex.java
│   ├── Crypto.swift           # AES-128-ECB / SHA1 / HMAC-SHA1（CommonCrypto）
│   ├── Frame.swift            # 20 字节帧、CRC8、btrand 派生
│   ├── Logic.swift            # 决策纯函数（与 Logic.java 一一对应）
│   ├── Power.swift            # 省电纯函数
│   ├── RunLog.swift           # 日志落盘
│   └── Store.swift            # UserDefaults
├── Net/
│   ├── NetClient.swift        # TCP 3050：8 位长度 + JSON + HMAC
│   └── CarAPI.swift           # 登录 / 状态 / 开锁 / 锁车
├── Ble/
│   └── BleCentral.swift       # CoreBluetooth 重写
├── Auto/
│   └── AutoEngine.swift       # 事件驱动的自动模式
├── UI/
│   ├── Theme.swift
│   ├── LoginView.swift
│   ├── MainView.swift
│   └── DiagView.swift
└── Assets.xcassets/           # AppIcon
```

协议层与 Android 完全一致，可以拿实车日志逐帧对照：

- `FF 12 11 ...` 握手（key = btkey）
- `FF 12 12 ...` 业务（key = btrandkey + "FFFF"）
- 状态帧 `type=0x69`，`body[5] & 0x20` = 已锁
- 开锁 payload `01`，锁车 payload `00 01`

## 8. 改完代码怎么重新出包

改完直接：

```bash
git add -A
git commit -m "改了 xxx"
git push
```

GitHub 会自动重新编译，出新的 ipa。**装新版本前不用卸载旧的**，巨魔直接覆盖安装，登录状态和参数都保留。
